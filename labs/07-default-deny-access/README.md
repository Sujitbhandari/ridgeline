# Lab 07: Default deny and self-service access

Most platform-team interrupts are some version of *"service X can't reach Y,
can you open it up?"*. This lab is that ticket, end to end: what the failure
looks like, how to prove it's the network policy, and how the fix becomes a
reviewed, expiring pull request instead of a hand-applied exception.

## How access works here

- Every tenant namespace starts with `default-deny-all` (generated by Kyverno).
- The golden-path chart opens only what every service needs (DNS, telemetry,
  Prometheus scraping, declared callers).
- Everything else comes from an **AccessRequest** in `access-requests/`.
  `accessctl` validates it against the catalog and renders the NetworkPolicies
  (and, on AWS, the IAM policy for the workload's IRSA role). Argo CD applies them.

## Break it

```bash
make load RPS=50 DURATION=10m
scripts/lab.sh apply labs/07-default-deny-access broken   # the grant "expires"
```

## Observe

- k6: 100% failures. verify-api returns `503 risk scoring unavailable`.
- verify-api logs: `risk-scorer unreachable ... "error":"ConnectTimeout"`.
- Jaeger: the `risk-scorer.score` span errors after the 2s timeout and
  **there is no risk-scorer span at all**. The request never arrived. That's
  the tell for network policy versus an application error.

## Diagnose

```bash
kubectl get networkpolicy -n identity
kubectl get networkpolicy -n risk
# Prove it from inside the pod (the image has Python but no curl, by design):
kubectl exec -n identity deploy/verify-api -- python -c \
  "import socket; print(socket.gethostbyname('risk-scorer.risk.svc')); socket.create_connection(('risk-scorer.risk.svc', 8080), 3)"
```

DNS resolves (DNS egress is allowed); the TCP connect raises `TimeoutError` (dropped,
not refused). A refused connection would mean "nothing listening"; a timeout
under default-deny means "something dropped it".

## Fix it the platform way

```bash
go run ./tools/accessctl explain access-requests/lab/verify-api-to-risk-scorer.yaml
scripts/lab.sh apply labs/07-default-deny-access fixed      # Argo CD restores the grant from git
```

`explain` prints what a reviewer sees on the PR: workload, target, ticket,
expiry, and which teams must approve (here, `@ridgeline/risk`, because they
own risk-scorer). Try editing the request to see the guardrails:

- remove `expires` → rejected (no standing access)
- set `expires` 120 days out → rejected (lab max is 90)
- add `s3/verification-records` → rejected without a risk exception, and routed to security
- add `actions: ["sqs:*"]` on a queue → rejected (no wildcards)

Finally, find what's about to expire across the repo:

```bash
go run ./tools/accessctl expired -within 30 access-requests/
```

In CI, a nightly job runs this and opens a PR deleting expired requests;
merging it removes the NetworkPolicies and IAM grants. Nobody has to remember.
